## 設定変更（Run 3）

Run 2 で 125 秒の長大ギャップが発生したため、ストレススクリプトのメモリ計算ロジックを変更:

| 変更項目 | 旧 (Run 1 / Run 2) | 新 (Run 3) |
|---|---|---|
| メモリ確保量 | `MemTotal × 80%` | `MemTotal − MID_MAX_MB(4096) − OS_BUFFER_MB(512)` |
| MID Java の余裕 | 4096MB を奪う可能性 | 4096MB を必ず残す |

## 観察

設定変更により Run 1 並みの結果に戻り、再現性が確保された:
- 最大ギャップ 40 秒（閾値 60 秒）でクリア
- 平均ギャップ 13.3 秒（Run 1 の 13.6 秒とほぼ同等）
- 上位 5 件のギャップは 27〜40 秒、いずれも閾値内

Run 2 の長大ギャップは「MID Java のヒープ確保まで奪い、GC が長引いた」ことが原因と確定。本番の MID Server では Java Max ヒープ 4096MB の温存が必須。
