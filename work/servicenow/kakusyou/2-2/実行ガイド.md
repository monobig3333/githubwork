## 0. 構成のおさらい

Mac から Zabbix へは **HTTPS 443 のみ**通信可、かつ Zabbix は 6.0（`history.push` API なし）。
そのため「Zabbix サーバ上で `zabbix_sender` を実行する Script」を `script.execute` API で呼ぶ方式。

```
Mac (python)  --HTTPS--> Zabbix Server --localhost:10051--> trapper item
                                              │
                                              ▼
                                        Trigger → MID → ServiceNow em_event
```

### ⚠️ 前回の実績と論点（計画書 D3）

2026/6/2 の前回計測は以下だった。

| 項目 | 前回値 | 目標 |
|---|---|---|
| success | 29,120 | 30,000 |
| failed | **880** | 0 |
| elapsed | **1,701 秒** | 600 秒 |
| 実効 rps | **17.6** | 50 |

失敗はすべて Zabbix 側の `Read timed out`（Mac → Zabbix の HTTPS）。
**同条件なら再現する見込み**なので、判定基準「処理漏れ・スキップなし」に対する
扱い（Zabbix 側の性能限界として注記するか）を事前に合意しておくこと。

CLAUDE.md の「学び 7」にも、Zabbix コネクタのバースト時取りこぼし（発生率 0.02%、
ServiceNow サポート確認済の既知事象）が記録されている。

## 6. トラブルシュート

| 症状 | 原因 / 対処 |
|---|---|
| `ZABBIX_SCRIPT_ID is not set` | `.env` 未設定。`--list-scripts` で確認 |
| `script.execute: Permission denied` | ユーザにスクリプト実行権限なし。Zabbix admin に依頼 |
| `Host not found` | ホスト名の書式ずれ。1-2 章のスクリプトで実名を確認 |
| `Read timed out` が多発 | Zabbix 側の処理限界。`--parallel` を下げるか分割投入 |
| ServiceNow に届かない | Zabbix トリガー未発火 / MID 経路。`python3 N-common/check_zabbix_connector.py --name zabbix` で確認 |
| `Cannot execute on Zabbix proxy` | Script の Execute on を `Zabbix server` に変更 |
