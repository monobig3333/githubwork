# 7-4 単一障害時のサービス継続性 — 試験方式と判定

## 要件
ServiceNow インスタンスの単一障害（サーバ・コンポーネント障害）時にも
業務が継続し、主要機能（インシデント管理/問題管理/構成管理/アラーム監視）が
継続利用できることを確認する。

## 試験方式: ドキュメントレビュー（実機試験は実施不可）

### 背景
本要件はもともと SN 担当者にテスト実施を依頼し、可能であれば
Playwright で主要機能の疎通を自動確認する想定だった。

しかし **ServiceNow 社は SaaS インスタンスの冗長化試験
（顧客向けの単一障害注入試験・フェイルオーバー試験）を実施しない方針**
であることが確認された。サーバ停止操作も SaaS 利用者側では不可能である。

### 採用した代替方式
ドキュメントレビューで要件充足を確認する:

1. ServiceNow SLA 資料・仕様書での単一障害時の業務継続保証
2. ServiceNow Trust Center の高可用性アーキテクチャ説明
3. コンポーネント冗長化（アプリノード・DB・ロードバランサ）の構成資料

### 確認するエビデンス
- 単一障害発生時に業務が継続する旨の記載
- 障害からの自動回復時間（5分以内回復等）の保証
- N+1 冗長やクラスタ構成の説明

## 判定
🟡 ドキュメントレビューによる確認（実機試験は ServiceNow 社方針により実施不可）

仕様書で単一障害時の業務継続・回復時間が保証されていることが
確認できれば合格とする。

## 備考
- ServiceNow 社が顧客向けにインスタンス冗長化試験・障害注入試験を
  実施しないことは本評価における制約事項として記録する。
- 試験計画書の「実機試験の場合」の条項は適用外となる。
- なお MID Server の冗長性（M-5〜M-9）は顧客自身のインフラ（AWS）上で
  あり、こちらは実機試験が可能。本要件（7-4）とは切り分けて扱う。
