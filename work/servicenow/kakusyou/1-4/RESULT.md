## 試験方式についての注記

Playwright で **画面から** 1,000 件を連続起票した。以下 2 点、前回（2026/5/18）から実装を変更している。

1. **iframe 対応**: Classic UI のコンテンツは `iframe#gsft_main` の中にあり、トップレベル `page` への
   `fill()` では要素が見つからない。`snow_goto_and_wait()` 経由でコンテンツロケーターを取得する方式に変更。
2. **保存ボタンを Submit に変更 (`PERF_SUBMIT_MODE=submit`)**: 従来の「保存して留まる」
   (`sysverb_insert_and_stay`) はレコードを開いたまま次へ進むため、**4〜5 件でセッションが詰まり
   `page.goto` が 30 秒タイムアウトし続ける**事象が発生した。通常の Submit に変えることで 1,000 件を
   連続実行できるようになった。

Submit 方式では保存後に一覧へ戻るためフォームから番号を取得できない。そのため
`short_description` に `[run=<tag>]` を埋め込み、**実行後に REST API で突合**して番号を取得している。

- run タグ: `1787100904`
- REST 突合結果: **1,000 件**（UI 側の成功数と一致）
- ブラウザコンテキスト再作成: 19 回（50 件ごと）
