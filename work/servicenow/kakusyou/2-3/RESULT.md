## 試験方式

1. `auth.json` の SSO 済みセッションでイベントビューワー (`em_event_list.do`) を開く
2. 別端末（Zabbix サーバ）から `send_bulk.py` で **1 件/秒**の通常流量を投入
3. `em_event` を `sys_created_on > 計測開始時刻` でポーリング（cookie + `X-UserToken` 認証）
4. 新規イベントごとに `sys_created_on (UTC)` → ビューワー DOM への描画完了までを計測

- 投入: ホスト `test-servicenow-monohyouka-00001`〜`00400` を 1 件/秒
- 描画モード: **top-page**（`em_event_list.do` を直接開くため iframe 経由ではない）

## 観察事項

1. **通常流量では描画遅延は安定**。2-2 で観測された「約 3,000 件を約 215 秒間隔でまとめて到達」
   というバースト特性は、1 件/秒の低流量では発生せず、素直に流れている
2. 最大 2.992 秒 / 平均 2.046 秒。ばらつきは小さい
3. 1 回目の試行（14:35〜)は 19/20 件を取得した時点で投入（200 件 = 200 秒）が尽き、
   20 件目待ちでタイムアウトした。投入量を 400 件に増やして再実施し完走。
   1 回目の 19 件も全て 3 秒以内（最大 2.970 秒）で、本結果と整合する

## 試験手順上の注意

Zabbix は OK → PROBLEM の遷移でしかイベントを生成しないため、投入前に対象ホストの復旧が必要。

```bash
python3 send_bulk.py --start 1 --count 400 --rate 50 --value 0   # ① 復旧
# ② 復旧イベントが ServiceNow に着地するまで待つ（約 4 分）
pytest 2-3/ -v -s                                                 # ③ 計測開始（Enter 待ち）
python3 send_bulk.py --start 1 --count 400 --rate 1               # ④ 通常流量で投入
```

計測に必要な件数（20 件）に対し、投入は十分な余裕（400 件 = 約 7 分）を持たせること。
