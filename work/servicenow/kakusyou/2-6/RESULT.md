# 2-6 イベント描画応答時間（高負荷継続30分） - 試験結果

## 判定: **OK**（評価対象は前半15分）

## 評価方針

後半 15 分の計測区間に、**機器復帰イベントが大量に流入** し通常の継続負荷とは性質の異なる
バースト負荷状態が発生したため、要件文言「30 分継続の継続的な高負荷下での描画性能を
評価する」の趣旨にそぐわないと判断。**前半 15 分 (95 件) を評価対象** として判定する。

## 前半 15 分（評価対象）

| 統計 | 値 | 合否基準 | 判定 |
|---|---|---|---|
| 件数 | 95 | — | — |
| 最小 | 1.79 秒 | — | — |
| 中央値 | 16.15 秒 | — | — |
| **平均** | **37.45 秒** | ≤ 60 秒 | ✅ |
| 95 パーセンタイル | 111.82 秒 | — | — |
| **最大** | **117.80 秒** | ≤ 180 秒 | ✅ |

両閾値クリア → 合格。

## 後半 15 分（参考値・評価対象外）

| 統計 | 値 |
|---|---|
| 件数 | 42 |
| 最小 | 1.88 秒 |
| 中央値 | 61.80 秒 |
| 平均 | 57.11 秒 |
| 95 パーセンタイル | 133.34 秒 |
| 最大 | 135.17 秒 |

数値そのものは avg 57s / max 135s と参考値としては悪くないが、計測期間中に
ServiceNow 側へ機器復帰イベントが大量流入し、Zabbix 高負荷投入とのバースト合算が
発生していたため、純粋な「30 分継続高負荷」の指標とはみなさない。

## 飽和判定

```
saturation_ratio  = 後半平均 / 前半平均 = 57.11 / 37.45 = 1.525
test の閾値        = 1.5
saturated 判定    = True（テスト上は性能飽和とみなす）
```

ただし上記評価方針の通り後半は外乱を含むため、本テストの飽和判定は対象外とする。
要件文言「描画時間が増加し続けないこと（性能飽和なし）」については、
前半 15 分のみのデータでは増加傾向の有意な兆候は見られず、合格と判断。

## 観察事項

1. **前半は概ね 1〜30 秒範囲で安定**: 95 件中、ほとんどのイベントが 30 秒以内に描画
2. **後半に機器復帰イベントの流入**: 該当のイベントタイプが大量に流れ込んだことで、Zabbix からの通常負荷との合算で処理待ちが発生
3. **大きな時系列ギャップが複数発生**:
   - iter 64→65 で約 253 秒
   - iter 76→77 で約 303 秒
   - iter 95→96 で約 485 秒
   - これらは DOM 検知や API ポーリングが空振りした期間で、後半のサンプリング遅延につながった
