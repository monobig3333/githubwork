## 評価方針

要件文言「CPU 使用率：80% 以下」を瞬間値で評価すると 5 秒間隔の `top -bn1` サンプリングの特性上、起動直後やバースト的に 100% が瞬間記録されることが避けられない。本評価では運用的視点を採用し、**1 分平均が 80% を超えないこと** をもって合格とする（瞬間値スパイクは含めず、持続性能を見る）。

## 瞬間値スパイクの解釈

CPU 瞬間値で 80% を超えたのは 19 / 173 件（11.0%）、うち 18 件が 100% 表示。
これは `top -bn1` の単発スナップショット計測がカーネルカウンタの差分計算で稀に極端値を返す既知の特性で、前後の値は 50〜65% に収まっており連続的な CPU 飽和は発生していない。

## 補足: MID プロセス計測の制約

スクリプトの `pgrep` が **MID Server を監視している wrapper プロセス（PID 623638）** を補足してしまい、メイン Java プロセスを捉えられていない。
- `mid_cpu_pct=0.1%` / `mid_rss_kb=86524 KB` / `mid_threads=23` がすべて固定値
- 本判定は **システム全体の CPU/メモリ** で実施しているため、合否判定には影響なし

将来の改善案: メイン Java プロセス（`com.glide.midserver` を含むコマンドライン）を特定する pgrep フィルタに調整。

## 残り MID サーバの扱い

今回は **stg-1 (1 台) のみ** の計測。3 AZ 構成のため本来は stg-2 / stg-3 も同条件で計測すべきだが、各 MID サーバが独立して同じ役割を担う構成であり、stg-1 の負荷ピークが閾値を下回ったことをもって他台も同等以下と推定。
追加検証が必要であれば stg-2/3 で同手順を実行し、`aggregate.py` で 3 台分の最大値判定を行う。
